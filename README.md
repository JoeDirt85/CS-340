## How do you write programs that are maintainable, readable, and adaptable? Especially consider your work on the CRUD Python module from Project One, which you used to connect the dashboard widgets to the database in Project Two. What were the advantages of working in this way? How else could you use this CRUD Python module in the future?
To write programs like such, I tend to find it helpful to start by breaking the overall problem into smaller, more solvable pieces, so that I may try to find solutions that can be used together to find 
and overall solution. Working this way also helps by creating small wins that help give confidence when these smaller pieces are solved. I will also add inline comments to not only help me better understand my code 
but also benefit those who may not be familiar with it. With my work for CRUD Python module, this allowed me to not think of the project as a whole but rather allowed me to think about the individual pieces such as the create, read, update and delete methods that were used to interact with the database. The way that this module was built, it could be slightly altered to work with other databases. 

## How do you approach a problem as a computer scientist? Consider how you approached the database or dashboard requirements that Grazioso Salvare requested. How did your approach to this project differ from previous assignments in other courses? What techniques or strategies would you use in the future to create databases to meet other client requests?
I start by reviewing the problem and figure out the constraints and reword the problem so that I may better understand it or look at differently. I will then create a rough structure of the various components that 
are needed to make up the problem as a whole. Doing this creates a bunch of smaller problems, that I can then work on and break down if the scope still is too large for me to solve. From here, I can then work on what 
I feel most comfortable with and can move to a different problem if I find myself having trouble. Often times, this method helps me to not get frustrated when I can't find a solution and sometimes solving a different 
problem can lead to me discovering a solution for another one. In previous courses, the projects were often smaller or didn't require different layers of the program, so I did not need to use the same strategy. But going 
forward, I can take the idea of breaking larger problems into smaller ones to help me in future projects.
